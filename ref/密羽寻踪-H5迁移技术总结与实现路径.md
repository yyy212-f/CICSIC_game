## 三、H5 技术选型总结

### 3.1 推荐技术栈

| 层次 | 方案 | 选型理由 |
|------|------|---------|
| **框架** | Vue 3 + TypeScript | 轻量、生态成熟，适合响应式 H5 |
| **构建** | Vite 5.x | HMR 极快、Tree-shaking 优秀 |
| **2D 渲染** | PixiJS 8.x | 轻量 WebGL 引擎，适合剧情叙事 |
| **状态管理** | Pinia | Vue 3 官方推荐，TS 完备 |
| **动画** | GSAP 3.x | 时间线精准，适合剧情动画 |
| **音效** | Howler.js | 多格式兼容 |
| **路由** | Vue Router 4.x | SPA 页面管理 |
| **持久化** | idb-keyval (IndexedDB) | 离线存档，轻量封装 |
| **后端(可选)** | 微信云开发 / Supabase | 组队/打卡/统计 |

### 3.2 关键决策说明

1. **PixiJS 而非 Cocos2d-H5**：核心是剧情叙事 + 选项交互，不是重度动作游戏。PixiJS 更轻量灵活
2. **独立 SPA H5**：当前只面向浏览器，以 HTTP 静态服务器或 CDN 发布；未来采用 WebView 封装时可复用 H5 业务层。
3. **MVP 无后端**：单人体验完全前端实现，存档存 IndexedDB。任何涉及账号、协同、位置或实体权益的功能均不进入当前版本。

## 四、核心架构设计

### 4.1 整体分层架构

```
┌─────────────────────────────────────────────────────┐
│                  H5 SPA (Vue 3 + TS)                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────────┐ │
│  │ Vue Router│ │  Pinia   │ │   PixiJS 渲染层      │ │
│  │  页面路由  │ │  全局状态  │ │  场景/地图/角色/特效  │ │
│  └──────────┘ └──────────┘ └──────────────────────┘ │
│  ┌────────────────────────────────────────────────┐ │
│  │              叙事引擎 (核心)                     │ │
│  │  FSM 状态机 │ 数值系统 │ 条件评估器 │ 存档管理  │ │
│  └────────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────────┐ │
│  │              数据层                             │ │
│  │  IndexedDB(存档) │ JSON(剧本/题库) │ OSS(图片)  │ │
│  └────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 4.2 叙事引擎——本项目最核心的技术模块

这是整个项目复杂度最高的部分，需要实现一个 **JSON 驱动的叙事引擎**。

**核心设计原则**：
- 剧本与引擎分离：所有剧本内容放在 JSON 中，引擎只负责解释执行
- 状态机模型：每个"场景"是一个状态，选项驱动状态迁移
- 数值联动：三大隐性数值（怀疑/洞察/信念）在节点中自动计算
- 条件门控：NPC 对话和选项的出现与否，由数值条件控制

**引擎运行时流程**：
```
加载剧本JSON → 解析为SceneGraph → 进入场景 → 设置背景/BGM
→ 执行节点列表：
  - dialogue/narration: 打字机显示文本 → 等待点击
  - choice: 显示选项 → 条件过滤 → 执行effects → 跳转
  - condition: 评估数值 → 跳转至对应分支
  - action: 执行效果 → 继续
  - ending: 显示结局 → 存档结算
→ 每次节点迁移后自动存档
```

## 五、五大功能模块技术要点

### 5.1 全域探索地图

| 功能点 | 实现方案 |
|--------|---------|
| 手绘地图渲染 | PixiJS Sprite 分层：底层地图背景 + 上层 POI 标记 + 情报鹰 Sprite |
| 情报鹰移动 | 点击/触摸目标点 → PixiJS Tween 沿路径平滑移动（150px/s, Power2.easeInOut） |
| POI 点击 | 弹出对应功能模态窗口（情报站/电影院/打卡点/市集） |
| 探索模式 | 自由探索（无约束）/ 任务探索（POI 带引导标识）；组队探索待后续规划 |
| 轨迹记录 | PathRecord 数组存坐标 → Canvas 绘制虚线 → 支持截图分享 |
| 跨世界锁定 | 前置世界完成度 + 关键道具持有数作为门控条件 |

### 5.2 情报站（线索传递中心）

- 每个世界地图分布多个情报站，作为任务节点
- 核心交互：密码验证（摩斯密码/选择题/数字密码）、情报交接、线索分析
- 奖惩机制：成功→羽毛+密码箱+情报碎片；失败→清空路线道具+暂停世界进度
- 密码箱：每日 3 次，阅后即焚效果

### 5.3 电影院 + 答题

- 视频播放：`<video>` 标签 + 自定义控制栏
- 按世界分类：7 部影片 × 2 题 + 62 道国安知识题
- 答题规则：答对→奖励；答错可重做；累计 3 次错→重新观看对应片段
- 支持投屏/班级集体模式

### 5.4 情报碎片·故事收集

- 碎片获取：完成任务/答题/打卡后解锁
- 碎片分组：每组 3-5 片段，集齐→合成动画→解锁完整故事+隐藏剧情
- 线下打卡联动：待后续规划；当前仅展示静态场馆与纪念内容
- 淬火 1937 进阶：五回合设计（窃火/暗渡/余烬/镜渊/归途）

### 5.5 商城市集

- 多货币体系：羽毛（基础）/ 破译情报（进阶）/ 一枝花（稀有）
- 兑换：当前仅发放本地虚拟道具；实体商品、兑换码与核销待后续规划
- 盲盒：概率表 JSON 配置 + 保底机制 + GSAP 抽取动画

## 六、数据持久化方案

### 6.1 存储结构

```
IndexedDB (idb-keyval):
├── playerProfile       # 姓名、代号、情报鹰装扮
├── stats               # 怀疑/洞察/信念/信任度/担忧值
├── chapterProgress     # 各章节完成度、历史选择
├── inventory           # 道具、羽毛、情报、花
├── worldUnlock         # 七大世界解锁状态
├── dailyBox            # 密码箱每日次数
├── quizProgress        # 答题记录
├── collectibles        # 碎片收集进度
└── saveSlots           # 多存档槽位 (最多3个)
```

### 6.2 存档策略

- 自动存档：每次关键节点切换时
- 手动存档：3 个存档位
- 版本号管理：防止 Schema 变更后兼容性问题
- 存档导出/导入：支持本地备份

## 十、总结

### 核心要点

1. **项目本质**：这是一个**剧情驱动的叙事互动游戏**，不是动作游戏。核心复杂度在叙事引擎（FSM + 数值系统 + 条件分支），不在渲染。
2. **内容已有**：淬火 1937 的完整剧本（序幕+七回+终章）、分支选项、数值影响、题库、英烈素材全部齐备，只需结构化转录为 JSON。
3. **技术路线清晰**：Vue 3 + PixiJS + 叙事引擎 + IndexedDB，MVP 阶段无需后端。
4. **分阶段交付**：先做叙事引擎 + 淬火 1937（约 10 周），再做五大功能模块（约 4 周），最后封装上线（约 2 周），总计约 16 周可交付完整 MVP。
5. **赛事节奏**：2026 年 8-9 月报名，11 月总决赛，需在 9 月前完成可用的 H5 版本。
