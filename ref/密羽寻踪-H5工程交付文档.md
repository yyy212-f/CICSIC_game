# 第一章 项目总览

## 1.1 产品定位

面向 15-25 岁青年群体的国家安全教育沉浸式互动平台，以独立 H5 为当前交付载体，以原创数字 IP "情报鹰"为情感纽带。核心价值：**"在玩中学、在学中悟"**——用剧情化探索替代传统说教。

**本版为纯静态单机版**：剧本、图片、音效、题库等静态资源随 H5 构建产物发布，无任何服务端依赖。开发和验收通过 HTTP 静态服务器在桌面及移动浏览器进行；不将直接打开 `index.html` 作为验收方式。

## 1.2 七大国安主题世界

| 世界 | 时间背景 | 核心任务 | 关键知识点 |
|------|---------|---------|-----------|

| **淬火 1937** | **七七事变后抗战全面爆发** | **潜入敌后，藏匿物品、秘密传递情报、接触作战计划** | **十六字方针：荫蔽精干、长期埋伏、积蓄力量、以待时机** |

# 第二章 技术架构与选型

## 2.1 整体架构

```
┌───────────────────────────────────────────────┐
│               H5 SPA 应用                       │
│            Vue 3 + TypeScript + Vite            │
├──────────────────┬────────────────────────────┤
│   2D 渲染层       │    业务逻辑层                │
│   PixiJS 8       │  - Pinia 状态管理            │
│   (WebGL 加速)    │  - 叙事引擎 (FSM)            │
│   + GSAP 动画     │  - 数值系统                  │
│   + Howler.js 音效│  - 路由 (Vue Router)         │
├──────────────────┴────────────────────────────┤
│              纯静态数据层                        │
│    public/data/*.json  (剧本/题库/碎片/配置)     │
│    public/images/*    (场景/角色/UI 贴图)        │
│    public/audio/*     (BGM/音效)                │
│    localStorage + IndexedDB (游戏存档)           │
└───────────────────────────────────────────────┘
```

**关键特性**：
- `npm run build` 后生成纯静态文件，可通过任意 HTTP 静态服务器或 CDN 运行
- 开发时 `vite dev` 直接热更新，无需任何后端服务
- 当前验收范围是桌面与移动浏览器；未来若采用小程序 `web-view`，H5 业务代码保持独立，不引入小程序 API

## 2.2 关键技术选型

| 层次 | 方案 | 版本 | 选型理由 |
|------|------|------|---------|
| 框架 | Vue 3 + TS | 3.4+ | 轻量、适合响应式 H5 |
| 构建 | Vite | 5.x | 纯静态输出，零后端搭建 |
| 2D 渲染 | PixiJS | 8.x | WebGL 加速，适合 2D 叙事场景 |
| 状态管理 | Pinia | 2.x | Vue 3 官方推荐 |
| 动画 | GSAP | 3.x | 时间线控制精准 |
| 音效 | Howler.js | 2.x | 多格式兼容，Sprite audio |
| 路由 | Vue Router | 4.x | SPA 页面管理 |
| 持久化 | idb-keyval | — | IndexedDB 轻量封装（3kB） |

## 2.3 关键决策

1. **PixiJS 而非 Cocos2d-H5**：核心玩法是**剧情叙事 + 文本选择**，非重度动作游戏。PixiJS 更轻量，地图场景用 Sprite 分层即可。
2. **独立 SPA H5**：先以标准浏览器为运行环境，专注叙事、地图与本地存档。未来采用 WebView 封装时可复用 H5 业务层；若改为原生小程序，则渲染、路由和存储层需重写。
3. **完全无后端**：所有逻辑在浏览器本地执行。存档存 IndexedDB，题库答案本地比对，碎片解锁条件本地校验。虚拟奖励仅用于本地体验，不作为可交易或可核销权益。

# 第三章 叙事引擎规格

## 3.1 引擎设计目标

- JSON 驱动：所有剧本内容放在 JSON 中，引擎只负责解释执行
- 状态机模型：每个"场景"是一个状态，选项驱动状态迁移
- 数值联动：三大隐性数值（怀疑/洞察/信念）在节点中自动计算
- 条件门控：NPC 对话和选项的出现与否，由数值条件控制

## 3.2 剧本数据 Schema

```typescript
interface Script {
  meta: {
    id: string;           // "tempered_1937"
    title: string;        // "淬火1937"
    version: string;      // "1.0.0"
    author: string;
  };
  chapters: Chapter[];
  initialStats: PlayerStats;
  initialInventory: string[];
}

interface Chapter {
  id: string;             // "prologue" | "chapter1" | ...
  title: string;
  scenes: Scene[];
}

interface Scene {
  id: string;
  bgImage: string;        // 相对路径，如 "images/scenes/chapter1/station.webp"
  bgm?: string;           // 相对路径
  ambient?: string;
  nodes: Node[];
}

interface Node {
  type: "dialogue" | "narration" | "choice" | "condition" | "action" | "ending";
  speaker?: string;
  content?: string;
  speakerImage?: string;
  choices?: Choice[];
  condition?: {
    stat: "suspicion" | "insight" | "conviction";
    operator: ">=" | "<=" | ">" | "<" | "==";
    value: number;
    passNodeId: string;
    failNodeId: string;
  };
  effects?: StatEffect[];
  inventoryChanges?: { add?: string[]; remove?: string[] };
  nextNodeId?: string;
  endingType?: "safe" | "caught" | "wavering" | "firm";
  endingDescription?: string;
}

interface Choice {
  text: string;
  effects?: StatEffect[];
  inventoryChanges?: { add?: string[]; remove?: string[] };
  nextNodeId: string;
  choiceId?: string;
  triggerEvent?: string;
  condition?: {
    stat: "suspicion" | "insight" | "conviction";
    operator: ">=" | "<=" | ">" | "<" | "==";
    value: number;
  };
}

interface StatEffect {
  stat: "suspicion" | "insight" | "conviction" | "trust_father" | "trust_org" | "worry";
  change: number;
}

interface PlayerStats {
  suspicion: number;
  insight: number;
  conviction: number;
  trust_father: number;
  trust_org: number;
  worry: number;
}
```

## 3.3 数值系统规格

| 数值 | 初始值 | 范围 | 作用 |
|------|--------|------|------|
| `suspicion` 怀疑值 | 0 | 0~99 | ≥30→被捕失败；≥16→被跟踪；部分选项门控 |
| `insight` 洞察值 | 3 | 0~20 | ≥5→火车站自动识别异常；≥3→自动发现便衣 |
| `conviction` 信念值 | 5 | 0~20 | ≤3→信念动摇；≥10→被捕逃脱判定；≥15→跨世界联动 |
| `trust_father` 父亲信任度 | 0 | -10~10 | 决定路费额度与介绍信 |
| `trust_org` 组织信任度 | 0 | 0~20 | 影响后续任务分配 |
| `worry` 担忧值 | 0 | 0~20 | 仅影响部分内心独白分支 |

### 数值间联动规则

```
suspicion >= 16 → 触发"被便衣跟踪"事件
suspicion >= 30 → 被捕结局（Game Over）

insight >= 3  → 自动发现门卫旁便衣（报纸拿反）
insight >= 5  → 火车站检票口识别 3 处异常

conviction <= 3  → 湘江边独白启用负面选项
conviction >= 10 → 被捕场景特殊逃脱判定 +1
conviction >= 15 → 解锁跨世界联动
```

## 3.4 叙事引擎运行时行为

```
1. 引擎 fetch("data/scripts/tempered_1937.json") → 解析为 sceneGraph
2. 进入场景 → 设置背景图/BGM → 执行节点列表
3. dialogue/narration 节点 → 打字机显示文本 → 点击确认
4. choice 节点 → 显示选项按钮 → 检查每个选项的 condition
   → 选中后执行 effects 和 inventoryChanges
5. condition 节点 → 评估玩家数值 → 跳转 passNodeId / failNodeId
6. action 节点 → 执行 effects → 继续下一节点
7. ending 节点 → 显示结局画面 → 存状态
8. 每次关键节点迁移后 → 自动存档至 IndexedDB
```

```typescript
interface WorldMap {

interface POI {
  id: string;
  type: "station" | "cinema" | "checkpoint" | "market" | "secret_meeting";
  x: number;
  y: number;
  label: string;
  icon: string;
  locked: boolean;
  unlockCondition?: { requireChapter?: string; requireItem?: string };
  action: "station" | "cinema" | "market" | "narrative";
}
```

### 探索模式（仅保留两种）

| 模式 | 行为 | 实现 |
|------|------|------|

| 任务探索 | 情报鹰发布主线，POI 流光引导，按序解锁 | 任务队列驱动，当前目标 POI 高亮 |

```

```

# 第七章 英烈故事碎片内容

## 淬火 1937 · 张永兴英烈碎片（5 片）

**分组 ID**：`tempered_1937_zhang_yongxing`
**故事原型**：抗战时期齐齐哈尔"波波夫"情报站敌后情报工作
**关联纪念场所**：齐齐哈尔革命烈士陵园

### 碎片一：入党与受命

> 那是我加入党组织的第二个年头，党内正是缺人的时候，在苏联学习的我义无反顾地把弟弟克兴推了出去，从此，情报工作便成了我们老张家一生都卸不下的担子……在经过了一年的系统性情报学习后，我先行回了国。那时正值全国抗日热潮，反"讨伐"斗争轰轰烈烈，街头巷尾，尽是民众救亡的呐喊。而这，不正是最好的掩护吗？"波波夫"情报站，顽强而固执地，在齐齐哈尔扎下了根。

### 碎片二：隐蔽侦察

> 岁月轮转，国相的身影恍又现眼前。瓜籽粒粒堆满山，夕阳巷口以风作探。不仅是风，那一草一木，满街尘土都可作我们的"探"。送货、修路、搬运货物，亦是我们"苦力"侦察组的日常。我们在日军军营、陆军医院、军用机场中穿行，掩去姓名样貌，一寸寸摸清了日军飞行队的机密，探明了其步兵、工兵的兵力部署与真实动向。

### 碎片三：杂货铺里的电波

> 你或许难以想象，为了传递情报，我们还经营着一间杂货铺吧！一年内，数段足以改变中国乃至共产国际的字段从我和克兴的眼前流过。只听"哒哒哒"地，谁能知道是算盘的串珠在响还是电台在熙攘中滋滋地转。

### 碎片四：被捕与酷刑

> 当我以为生活会这样美好下去时，命运给了我当头一棒……民国 25 年的九月，金黄的叶漱漱地落，我的生命也进入了倒计时。高立良、关奎群、蔡秀林、罗世环相继被捕，不出意外的，我们被连根拔起了。眼见诱降我不得，刺骨的凉水涌了进来。他们剥光我的衣服，将我绑在长凳上，嘴里、鼻孔里全是水，只等肚子灌满，便又骑在我身上粗暴地将水挤出。世间竟有如此毫无人性的酷刑！即便粉身碎骨，我们也必与日寇血战到底！

### 碎片五：就义与新生

> 江湖常有流传，祸不及家人也，可战争面前无道义。他们抓了我的妻女入宪兵队，我能做的只是隔着栅栏，两行清泪下……
>
> 民国 26 年，"枪决令"下无人生还，克兴与我结束了短暂的一生，没能等到全面抗战的那一天。永兴永兴，我为之而生，也在 22 年迎来了"新生"。我在黑暗中蛰伏，观那飞机升降，后方敌情，只为点燃北地的烛火，照亮共产主义者前行的征途。
>
> 你问我后悔吗？胞弟就义，妻女入狱，家老白头送终……或许有过刹那的痛楚。可倘若人人都只顾小家，舍弃家国大义，我们的祖国，又何来希望？我们的民族，又何以前行？

# 第八章 数据持久化 Schema

## IndexedDB 存储结构

```typescript
interface SaveData {
  version: string;              // 存档版本号
  lastSaved: number;            // 时间戳
  player: {
    name: string;
    codeName: string;           // 代号
    eagleOutfit: string;        // 当前装扮 ID
    ownedOutfits: string[];
  };
  stats: PlayerStats;
  inventory: {
    items: { [itemId: string]: number };
    feathers: number;
    intel: number;
    flowers: number;
  };
  progress: {
    currentWorld: string;
    chapterProgress: {
      [chapterId: string]: {
        completed: boolean;
        choices: { sceneId: string; choiceId: string }[];
        statsAtEnd: PlayerStats;
      };
    };
    worldUnlock: { [worldId: string]: boolean };
  };
  daily: {
    boxOpenedToday: number;
    boxDate: string;            // "YYYY-MM-DD"
  };
  quiz: {
    [quizId: string]: {
      wrongAttempts: number;    // 累计答错次数
      passed: boolean;
    };
  };
  collectibles: {
    fragments: { [fragmentId: string]: boolean };
    fragmentGroups: { [groupId: string]: { collected: number; complete: boolean } };
  };
  metadata: {
    playTime: number;
    totalChoices: number;
    endingsUnlocked: string[];
  };
}
```

## 实现

```typescript
// 使用 idb-keyval
import { get, set, del } from 'idb-keyval';
const SAVE_KEY = 'miyuxunzong_save';

async function saveGame(data: SaveData) {
  data.lastSaved = Date.now();
  await set(SAVE_KEY, data);
}

async function loadGame(): Promise<SaveData | null> {
  return await get(SAVE_KEY);
}

async function deleteGame() {
  await del(SAVE_KEY);
}
```

## 存档兼容

- 每次 Schema 变更递增 version
- 加载时 version 不匹配 → 执行迁移函数填充默认字段
