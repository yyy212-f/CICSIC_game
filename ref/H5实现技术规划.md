# 密羽寻踪 H5 实现技术规划文档

> 项目名称：密羽寻踪——"情报鹰"数字 IP 赋能下高校国家安全教育沉浸式传播模式研究
> 参赛赛事：中国国际大学生创新大赛（2026）
> 当前状态：已有 Unity Windows 版 demo（淬火 1937 主题世界），拟转为独立静态 H5

---

## 一、项目核心定位与产品概述

### 1.1 产品定位
面向 15-25 岁青年群体的国家安全教育沉浸式互动平台，以独立静态 H5 为当前载体，以原创数字 IP "情报鹰"为情感纽带，通过剧情化探索与任务互动实现"在玩中学、在学中悟"的教育目标。

> **当前范围**：仅规划可在桌面和移动浏览器运行的单人 H5 MVP。小程序封装、视频、组队、线下打卡、实体交易、账号及云端能力均为待规划功能，不进入当前排期、开发或验收。

### 1.2 七大国安主题世界（完整内容体系）

| 主题世界 | 历史背景 | 核心任务 | 关键知识 |
|---------|---------|---------|---------|
| **破晓 1927** | 四一二政变后白色恐怖 | 建立中央特科，情报书写、接头跟踪 | 党的隐蔽斗争专业化体系 |
| **淬火 1937** | 抗战全面爆发 | 潜伏敌后、藏匿物品、秘密传递情报 | 十六字方针：荫蔽精干、长期埋伏 |
| **决战 1948** | 解放战争战略决战 | 渗入作战厅、传递胶卷、策反师长 | 李克农与中情部，淮海战役情报 |
| **新生 1949** | 建国初期反特斗争 | 排查可疑电台、策反特务 | "以特反特"策略 |
| **潮涌 1983** | 改革开放国安部成立 | 监管涉外企业、预警被策反 | 反间谍与国家安全保障 |
| **无形 2022** | 数字时代网络安全 | 分析钓鱼邮件、排查系统漏洞 | 网络安全、数据安全、算法博弈 |
| **守望 2026** | 新时代反分裂斗争 | 参观纪念广场、学习国安知识 | 隐蔽战线英烈精神 |

> **当前重点**：淬火 1937 已拥有完整剧本（序幕 + 六回章节）、人物手绘、完整数值与分支系统设计。

## 二、技术选型建议

### 2.1 整体架构

```
┌─────────────────────────────────────────┐
│              H5 SPA 应用                  │
│   (Vue 3 / React 18 + TypeScript)        │
├──────────────┬──────────────────────────┤
│  2D 渲染引擎  │  业务逻辑层               │
│  (PixiJS /    │  (状态管理、剧情引擎、     │
│   Phaser /    │   数值系统、路由管理)      │
│   Cocos2d-H5) │                          │
├──────────────┴──────────────────────────┤
│       IndexedDB / localStorage 存档       │
└─────────────────────────────────────────┘
```

### 2.2 关键技术选型

| 层次 | 推荐方案 | 备选方案 | 说明 |
|------|---------|---------|------|
| **框架** | Vue 3 + TypeScript | React 18 + TS | Vue 3 生态成熟，适合响应式 H5 |
| **2D 渲染** | PixiJS 8 | Phaser 3 / Cocos2d-H5 | PixiJS 轻量、WebGL 加速、适合剧情交互场景 |
| **状态管理** | Pinia (Vue) / Zustand (React) | — | 管理玩家数据、全局状态 |
| **动画** | GSAP / Anime.js | CSS Animation | 复杂剧情动画、UI 过渡 |
| **音效** | Howler.js | Web Audio API | 背景音乐、音效触发 |
| **存储** | localStorage + IndexedDB | — | 存档持久化 |
| **后端** | 暂不采用 | 微信云开发 / Supabase | 当前单机 H5 无服务端；后续联机能力再评估 |
| **构建** | Vite | Webpack | 快速构建、HMR 开发体验好 |

### 2.3 关键设计决策说明

- **为什么用 PixiJS 而非 Cocos2d-H5**：项目核心是**剧情叙事 + 选项交互**，不是重度动作游戏。PixiJS 灵活轻量，地图场景可以用 Sprite + Tilemap 实现，不需要 Cocos 的全套游戏引擎。若后续需要复杂物理碰撞或大规模动画，再考虑迁移到 Phaser 3。
- **为什么先做独立 SPA H5**：当前只需浏览器运行，静态构建产物可部署到任意 HTTP 静态服务器。未来若采用 WebView 封装，可复用业务层；若改原生小程序，则需重写渲染、路由与存储层。
- **为什么暂不采用后端**：MVP 的单人体验和本地存档可完全前端实现。组队、打卡、统计、账号和实体权益均依赖服务端可信校验，统一放入待规划。

## 三、核心功能模块实现规划

### 3.1 情报鹰 IP 系统（贯穿全流程）

| 功能点 | 技术实现要点 |
|--------|------------|
| 形象创建与自定义 | Canvas 绘制 + 装扮 Sprite 叠加层，支持更换服装、皮肤、配饰 |
| 入口引导动画 | GSAP 时间线动画 + 对话气泡 |
| 剧情导航与任务发布 | 事件驱动系统，情报鹰作为 Narrator Agent |
| 密码箱 3 次/日 | localStorage 记录每日次数，阅后即焚（销毁内容 + 动画效果） |
| 羽毛 / 道具收集 | 全局状态管理 + localStorage 持久化 |
| 组队缔结契约 | 可选后端支持，通过云函数交换进度/数据快照 |

### 3.2 淬火 1937 剧情系统（核心叙事引擎）

这是整个平台最复杂的模块，Unity demo 的内容全部在此。

#### 3.2.1 叙事引擎架构

```
┌───────────────────────────────┐
│        剧本数据 (JSON)         │
│  ├─ 章节(Segment)             │
│  ├─ 场景(Scene)               │
│  ├─ 对话节点(DialogueNode)    │
│  ├─ 选项节点(ChoiceNode)      │
│  └─ 条件跳转(ConditionalJump) │
├───────────────────────────────┤
│        叙事引擎 Runtime        │
│  ├─ 状态机 (FSM)              │
│  ├─ 数值系统 (Stats)          │
│  ├─ 条件评估器 (Evaluator)    │
│  └─ 存档系统 (Save/Load)      │
├───────────────────────────────┤
│        渲染层 (PixiJS)         │
│  ├─ 场景背景 (静态图/Parallax) │
│  ├─ 角色立绘 (Live2D/静态)    │
│  ├─ 对话气泡 + 打字机效果    │
│  └─ 选项按钮 UI              │
└───────────────────────────────┘
```

#### 3.2.2 数值系统（三大隐性数值）

| 数值 | 范围 | 影响 | 实现方式 |
|------|------|------|---------|
| **怀疑值** | 0~30+ | 过高触发被捕结局 | 全局 Store 管理，关键节点检查阈值 |
| **洞察值** | 0~20+ | 高洞察解锁隐藏线索、特殊选项 | 条件门控 (Gate System) |
| **信念值** | 0~20+ | 影响意志类抉择的结果判定 | 与怀疑值联动校验 |

数值间联动逻辑示例：
- 洞察 ≥ 5 → 火车站检票口自动识别 3 处异常
- 怀疑 ≥ 16 → 登车触发"被便衣跟踪"事件
- 信念 ≥ 10 → 被捕场景可触发特殊逃脱判定

#### 3.2.3 剧本章节结构（淬火 1937）

| 章节 | 场景 | 核心玩法 |
|------|------|---------|
| 序幕 | 气象台地下室入党仪式 | 对话推进、宣誓交互 |
| 第一回 离校准备 | 宿舍收拾行李 | 物品管理、多选抉择、分支触发 |
| 特殊事件 | 深夜烧书 / 校工敲门 | 突发事件响应、隐藏数值判定 |
| 赠书支线 | 与张同学互动 | NPC 信任系统、隐藏道具获取 |
| 第二回 出校门 | 校门检查 + 便衣观察 | 环境观察 (洞察门控)、应答选择 |
| 第三回 登车 | 火车站检查 | 队列观察、行李搜查、被捕/通过 |
| 第四回 回家 | 武昌家中 + 与父母互动 | 信任度系统、家国两难抉择 |
| 第五回 临时大学 | 校园寻人 + 湘江边独白 | 内心抉择、状态影响 |
| 第六回 接头 | 与郭见恩接头 | 暗号匹配、道具使用 |
| 第七回 报名服务团 | 报名登记 | 三题问答、身份伪装 |
| 终章 | 登车赴西北 | 结局结算 |

#### 3.2.4 多结局系统

| 结局类型 | 达成条件 | 对应效果 |
|---------|---------|---------|
| 安全潜伏 | 全程怀疑值 ≤ 15，关键任务成功 | 进入后续章节 |
| 被捕失败 | 怀疑值 ≥ 30 或关键抉择选错 | Game Over，重来 |
| 信念动摇 | 信念值 ≤ 3 | 角色退缩，隐藏结局 |
| 信念坚定 | 信念值 ≥ 15 + 特殊条件 | 解锁跨世界联动剧情 |

#### 3.2.5 物品/道具系统

| 道具类型 | 示例 | 影响 |
|---------|------|------|
| 关键道具 | 团员证、接头路线、暗号纸条 | 推进剧情必需品 |
| 消耗品 | 路费、干粮 | 影响 NPC 信任度 |
| 收集品 | 情报碎片、纪念品 | 合成英烈故事，进入隐藏结局 |

### 3.3 全域探索地图

每个主题世界一张定制化地图，情报鹰为可操控角色，在地图中自由移动、解锁区域、触发事件。

| 需求 | 实现方案 |
|------|---------|
| 定制化手绘地图 | PixiJS Sprite 分层渲染：底层为高分辨率手绘地图背景，上层为 POI 标记与情报鹰 Sprite |
| 情报鹰操控 | 点击/触摸目标点 → PixiJS Tween 驱动鹰沿路径平滑移动 → 到达后区域解锁动画 |
| 功能点位 | 地图标注情报站、题库、碎片、虚拟市集、秘密接头点等 POI → 点击弹出对应功能模态窗口 |
| 探索模式 | 状态机控制：自由探索（无约束，可浏览场景）与任务探索（情报鹰发布主线，POI 带引导标识）；组队探索待规划 |
| 情报鹰记录轨迹 | PathRecord 数组存储坐标序列 → Canvas 绘制运动轨迹线 → 支持截图分享 |
| 资源收集动画 | 情报鹰在地图探索中"带回"情报碎片和虚拟纪念品；不依赖视频播放 |
| 阅后即焚 | 密码线索查看时启动销毁动画（燃烧/溶解效果），查看后状态置为已销毁，不可恢复 |
| 跨世界锁定 | 前置世界任务完成度 + 关键道具持有数作为门控条件，满足后解锁下一世界入口 |
| 世界切换 | 主世界选择界面以时间线（1927→2026）排列，锁/解锁状态通过锁图标 + 动效区分 |

### 3.4 情报站——线索传递中心

每个世界地图内分布多个情报站，承担情报交接、敌后潜伏、数字反诈等核心剧情任务。

| 需求 | 实现方案 |
|------|---------|
| 任务发布与提交 | 情报站作为任务节点，玩家在此接收/提交任务，触发剧情对话或数值判定 |
| 情报交接与密码验证 | 输入验证码/摩斯密码/选择题等形式校验，成功则推进剧情，失败触发风险机制 |
| NPC 引导 | 每个情报站配置专属 NPC，结合世界背景讲解保密知识（如破晓 1927 讲地下工作准则，无形 2022 讲数据安全规范） |
| 奖惩机制 | 成功：获得羽毛、密码箱次数、情报碎片、献花道具；失败：丢失当前路线所有纪念品与临时道具，暂停该世界探索进度，强化风险教育 |
| 密码箱 | 每日 3 次开启机会，内含密码线索、破译任务、羽毛、一枝花、道具卡。完成世界主线任务可获得密码本，额外增加开箱次数 |
| 跨模式复用 | 情报站逻辑同时支持自由/任务/组队三种模式，组队模式下多人共享任务进度 |

### 3.5 电影院 + 答题系统

> **待规划**：视频不纳入当前 MVP。以下仅保留后续数据设计参考；实施前需确认版权、转码、静态托管成本及移动端播放兼容性。

| 需求 | 实现方案 |
|------|---------|
| 视频播放 | 后续采用已取得授权的媒体文件与浏览器 `<video>`；不依赖第三方嵌入 |
| 影视内容分区 | 按世界分类：淬火 1937 专区上线《永不消逝的电波》《野火春风斗古城》《与魔鬼打交道的人》；决战 1948 专区上线解放战争纪录片；无形 2022 专区上线《惊蛰无声》及反诈短片 |
| 智能推荐 | 情报鹰根据用户当前探索进度推荐对应视频，如完成淬火第一章后自动推荐相关影片 |
| 观影后答题 | 视频播放完毕自动弹出答题 Modal，情报鹰弹出提示引导作答 |
| 题库结构 | JSON 配置，分影片互动题（7 部 × 2 题 = 14 题）和国安知识题（62 道单选），支持随机排序 |
| 答题奖惩 | 答对：获得羽毛、密码破译次数、情报碎片。答错可重做，累计答错 3 次需重新观看对应片段 |
| 投屏/集体模式 | 待规划；需教师端、同步协议与数据上报能力 |
| 题库可扩展 | 当前题库 JSON 独立于代码；后台编辑需服务端，待规划 |

### 3.6 情报碎片·故事收集系统

情报鹰探索中带回各世界的真实英烈情报碎片，集齐后合成完整故事。线下打卡联动为待规划功能。

| 需求 | 实现方案 |
|------|---------|
| 碎片获取途径 | 完成主线/支线任务、观影答题、线下打卡后条件解锁 |
| 碎片分组 | 每个世界对应多组英烈碎片，每组 3-5 个片段（潜伏经历、情报传递、牺牲场景） |
| 碎片呈现形式 | 文字故事 + 历史场景提示 + 核心精神提炼，标注英烈所属纪念场馆信息 |
| 淬火 1937 进阶碎片 | 按"窃火、暗渡、余烬、镜渊、归途"五回合设计，每回合对应核心谍战情节、特色收集品与沉浸式玩法 |
| 碎片合成 | 集齐单组碎片 → 点击合成 → 动画效果 → 解锁完整英烈故事及隐藏剧情 |
| 线下打卡联动 | 待规划；当前仅展示静态场馆介绍 |
| 打卡验证 | 待规划；需服务端防作弊校验，不使用浏览器本地数据作为依据 |
| 线上献花仪式 | 待规划；当前可保留非定位的静态纪念内容 |
| UI 展示 | 卡片式左右滑动浏览，未解锁碎片显示剪影占位符，已解锁显示完整图文 |

### 3.7 商城市集·物资兑换

平台专属商城，多货币体系支撑道具与文创兑换。

| 需求 | 实现方案 |
|------|---------|
| 多货币体系 | 羽毛（基础货币）、破译后的完整情报（进阶货币）、专属道具（稀有货币），三层并行 |
| 可兑换物 | 当前仅含虚拟道具、装扮、线索提示卡与密码破译工具 |
| 兑换逻辑 | 本地检查货币量 → 扣减 → 发放虚拟道具 → 播放获得动画 |
| 线下实体兑换 | 待规划；需订单、库存和核销服务端 |
| 限量品管理 | 当前不做；本地存储不能作为库存或权益依据 |
| 盲盒机制 | 概率表 JSON 配置，随机算法保证保底次数，抽取动画用 GSAP 序列实现 |

## 四、数据与持久化方案

### 4.1 本地存储结构 (IndexedDB)

```
├── playerProfile       # 玩家档案：名称、代号、情报鹰装扮
├── globalStats         # 三大数值：怀疑/洞察/信念
├── chapterProgress     # 各章节解锁状态、完成度
├── inventory           # 道具列表：关键道具/消耗品/收集品
├── worldUnlock         # 七大世界解锁状态
├── dailyBox            # 密码箱每日次数 + 刷新时间戳
├── quizProgress        # 答题记录（答对/错次数）
├── collectibles        # 情报碎片收集进度
├── saveSlots           # 多存档槽位 (最多 3 个)
└── gameConfig          # 游戏配置（音量、语言等）
```

### 4.2 存档系统

- 自动存档：每次关键节点切换时
- 手动存档：开放 3 个存档位
- 存档版本号管理：防止数据结构变更后兼容性问题
- 存档导出/导入：支持本地备份

### 4.3 云存储（可选，二阶段）

| 数据 | 用途 |
|------|------|
| 用户注册信息 | 跨设备同步 |
| 组队数据 | 契约缔结、实时进度同步 |
| 线下打卡记录 | 防作弊验证、数据统计 |
| 活动日历 | 预约定时任务触发 |

## 五、UI/UX 设计要点

### 5.1 适配策略

- **设计稿基准**：375px × 667px (iPhone SE)
- **适配方式**：rem + vw/vh + 媒体查询
- **横屏锁定**：保持竖屏，用 CSS `orientation: portrait`
- **触摸交互优化**：选项按钮直径 ≥ 44px，留足点击区域

### 5.2 视觉风格

- 每个主题世界独立配色方案与 UI 皮肤（CSS 变量切换）
- 淬火 1937 风格：民国复古（暖棕、旧黄、墨绿、斑驳质感）
- 情报鹰 UI 组件：统一气泡、按钮、对话框风格

### 5.3 关键页面清单

| 页面 | 功能 |
|------|------|
| 首页/入职仪式 | 创建情报鹰、取代号、游戏介绍 |

## 八、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 内容审核（国家安全题材） | 高 | 提前对接政务审核，内容三级审核机制；素材脱敏处理 |
| 静态资源体积过大 | 中 | WebP/压缩音频、路由级代码分割、按需加载；视频不在 MVP 内 |
| 图片资源过大 | 中 | WebP 格式压缩，CDN 加载，按需加载（IntersectionObserver） |
| 离线存档丢失 | 低 | 多槽位自动存档 + 导出备份功能 |
| 待规划功能膨胀 | 中 | 视频、组队、打卡、实体交易不设当前排期和验收条件 |
| 团队技术力不足 | 中 | 叙事引擎用 JSON 配置化降低开发门槛，文档驱动开发 |

## 十一、关键提醒

1. **无需从零写剧本**：淬火 1937 的完整剧本、分支选项、数值影响，在 PDF 文档中已逐字写明，只需结构化转为 JSON 配置

4. **安全性考虑**：存档不上传明文敏感内容；线下打卡涉及真实纪念场所，需关注用户隐私
5. **赛事时间节点**：根据教育部通知，2026 年 8 月 10 日-9 月 25 日为报名期，11 月总决赛，建议 H5 版 MVP 在 9 月前可用
